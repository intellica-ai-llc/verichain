# L0 interface contracts (frozen at G1; parallel builders code against these)

Change control: only the spec steward edits this file. A builder who needs a change files a note in `docs/reports/contract_requests.md` and works around it.

## C1. Tile layout (C2SP `tlog-tiles`, tile height 8 = 256 hashes per full tile)
Hash tiles live at `tile/<L>/<N>` (level L, index N); partial tiles at `tile/<L>/<N>.p/<W>` (W = 1..255 hashes present). Entry bundles live at `tile/entries/<N>` and `tile/entries/<N>.p/<W>`. Index N is written as zero-padded decimal split in 3-digit groups, every group except the last prefixed with `x`, joined by `/` (e.g. N=1234067 -> `x001/x234/067`; N=5 -> `005`). Builders MUST read the spec (https://c2sp.org/tlog-tiles) and the independent vector author does the same; where this summary and the spec differ, the spec wins and the difference is reported.
Hashes are RFC 9162 SHA-256 with 0x00/0x01 domain separation (implemented in `vc-core::hash` and `vc-log`).

## C2. Store trait (crate `vc-store`)
```rust
pub trait Store: Send + Sync {
    fn put(&self, key: &str, bytes: &[u8]) -> Result<(), StoreError>;      // atomic and durable (fsync file + dir) on return
    fn get(&self, key: &str) -> Result<Option<Vec<u8>>, StoreError>;
    fn exists(&self, key: &str) -> Result<bool, StoreError>;
    fn list(&self, prefix: &str) -> Result<Vec<String>, StoreError>;      // sorted
}
```
Keys are relative, `/`-separated, no `..`, no leading `/`. Implementations: `FsStore`, `MemStore`. Writes are overwrite-safe only for partial tiles; full tiles and bundles are immutable (second put with different bytes returns `StoreError::Conflict`).

## C3. Tile log (crate `vc-log`, module `tilelog`)
```rust
pub struct TileLog<S: Store> { .. }
impl<S: Store> TileLog<S> {
    pub fn open(store: S, origin: &str) -> Result<Self, LogError>;          // recovers state from stored tiles
    pub fn size(&self) -> u64;
    pub fn root(&self) -> Hash;                                              // root of the current tree
    pub fn append(&mut self, entry: &[u8]) -> Result<u64, LogError>;         // returns index; durable before return
    pub fn entry(&self, index: u64) -> Result<Vec<u8>, LogError>;
    pub fn inclusion_proof(&self, index: u64, size: u64) -> Result<Vec<Hash>, LogError>;
    pub fn consistency_proof(&self, first: u64, second: u64) -> Result<Vec<Hash>, LogError>;
    pub fn root_at(&self, size: u64) -> Result<Hash, LogError>;
}
```
Appending is O(log n) hashing (no full-tree recomputation). Proofs are computed from stored tiles and MUST equal the slice-based functions already in `vc-log` (differential test). Crash safety: after a crash at any byte boundary the reopened log has a consistent prefix: never a root that does not match the stored entries.

## C4. Receipt v0 (JSON; later wrapped as a SCITT/COSE receipt)
```json
{"v":1,"origin":"<log origin>","leaf_index":7,"tree_size":10,"leaf_hash":"<hex>",
 "inclusion_proof":["<hex>", ...],"checkpoint":"<signed note text, as produced by vc_log::checkpoint::note>"}
```
The log entry is the COSE_Sign1 statement bytes; `leaf_hash = SHA-256(0x00 || entry bytes)`. The checkpoint's `size` must equal `tree_size`, and its root must equal the root recomputed from the proof.

## C5. Evidence pack v0 (JSON file; format of `vc-pack`/`vc-verify`)
```json
{"v":1,
 "trust":{"origin":"...","operator":{"name":"...","pubkey_hex":"..."},
          "witnesses":[{"name":"...","pubkey_hex":"..."}],"min_witnesses":2,
          "issuers":[{"kid_hex":"...","pubkey_hex":"...","max_completeness":"C2"}]},
 "entries":[{"statement_cose_hex":"...","receipt":{ ...C4... }}],
 "policy":{"min_completeness":"C1","min_assurance":"A0","max_open_intents":0}}
```
`vcv verify pack.json` exits 0 only if every check passes and prints a JSON report `{ "ok": bool, "checks":[{"name","ok","detail"}...] }`. Checks: COSE signature by a trusted issuer key; payload is valid JCS JSON conforming to the statement schema; receipt inclusion proof; checkpoint operator signature and independent witness quorum bound to the origin; per-agent chain rules over the entries in log order (gaps are reported, since a pack may be a subset: chain checks apply to the consecutive run provided and report `partial_coverage`); completeness and assurance minimums (statement `completeness` must not exceed the issuer's `max_completeness`); open-intent count.

## C6. Witness protocol (crate `vc-witness`, library API; HTTP binding later)
`Witness::add_checkpoint(note: &str, old_size: u64, proof: &[Hash]) -> Result<CosignedNote, WitnessError>`: verifies the operator signature for the configured origin; if the witness has no state for the origin it accepts only after trust-on-first-use is explicitly enabled; otherwise `old_size` must equal the witness's last-seen size and the consistency proof must verify from last-seen root to the new root; refuses (and records a reportable `Equivocation` error) if a checkpoint with the same size but a different root is presented; persists last-seen atomically before returning the cosignature; never cosigns a smaller size than last seen.

## C7. Out of scope for wave 1
HTTP servers/clients, anchoring (RFC 3161/OTS), PQ signatures, KMS, SDKs. Library APIs only.
